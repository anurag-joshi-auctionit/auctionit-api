Database seed pipeline — run in this order
============================================

Run from apps/api (or `pnpm --filter @auctionit/api <script>` from repo root).

Orchestrator: `./src/db/seed/seed.sh` runs the DB phases (A → C) and then the
file/document upload phase (R2) in order.

  ./src/db/seed/seed.sh              # full pipeline (DB phases + R2 uploads)
  ./src/db/seed/seed.sh --db-only    # DB phases A–C only, no R2 uploads
  ./src/db/seed/seed.sh --files-only # only file/document uploads to R2
  ./src/db/seed/seed.sh --clean      # dry-run truncate (row counts only)
  ./src/db/seed/seed.sh --clean-yes  # truncate default tables, then seed


Overview
--------

This folder is a MSSQL → Postgres migration ETL pipeline plus Postgres-only
reference seeds. It is NOT a minimal dev-fixture set.

  Phase A  — Postgres-only (no MSSQL env required)
  Phase B  — MSSQL → Postgres core entities and links
  Phase C  — MSSQL → Postgres dependent data (auctions, EMD)
  Phase R2 — File/document uploads to R2 (bidder docs, auction docs, SI docs)

The R2 phase is split out from the DB phases because those seeds fetch legacy
blobs/files and upload them to R2 (object storage), which needs R2 credentials
and is slower/networked. Run it via `--files-only`, or as the tail of the full
pipeline (default). It runs AFTER the DB phases so bidders/auctions and their
document-type rows already exist. seed:bidder-documents self-backfills
bidder_bank_accounts.cancelled_cheque_file_name, so it is safe to run after
seed:bidder-bank-accounts (Phase B).

MSSQL maintenance scripts (write to legacy MSSQL only, NOT Postgres) live in
`src/db/mssql-maintenance/` — see "MSSQL maintenance" at the bottom.


0. (Optional) Clean Postgres tables before re-seeding
-----------------------------------------------------

Dry-run first (prints row counts, deletes nothing):

    pnpm clean:db

Default truncate (RESTART IDENTITY CASCADE on material_locations, plant_locations,
clients, locations):

    pnpm clean:db --yes

`users` is NOT in the default clean target — pass --tables=users --yes to wipe it.

Override the table set:

    pnpm clean:db --tables=locations --yes

For a full re-migration you may need to truncate additional tables explicitly,
e.g. bidders, users, auctions, emd_transactions.

(No MSSQL_SERVER / MSSQL_* required)


A1. seed:locations — REQUIRED (prod + dev masters)
    Source: src/db/seed/data/cities.csv (India states + cities).
    Populates `locations` for resolving client/bidder location_id FKs.

A2. seed:roles — REQUIRED before seed:permissions and seed:users
    Source: src/db/schema/roles.ts (ROLE_CODES). Idempotent ON CONFLICT.
    Target codes: admin, account, kam, client, client_limited, bidder.
    Also remaps users still on legacy codes (account_admin → account, etc.)
    and drops unused obsolete role rows.
    After any roles change/remap, re-run seed:users (B1) so role_id
    stays consistent with the current role set.

        pnpm seed:roles


A2b. seed:permissions — REQUIRED for RBAC
    Upserts permission catalog + role_permissions defaults from @auctionit/authz.
    Run after seed:roles (role rows must exist). Safe to re-run (never disables

    Ensures users.id = 1 exists (minimal system user) so created_by /

=== Phase B — MSSQL → Postgres core ===
(Requires MSSQL_SERVER / MSSQL_PORT / MSSQL_USER / MSSQL_PASSWORD / MSSQL_DATABASE)


B1. seed:users — REQUIRED (prod)
    Source: MSSQL tbl_Config_User.
    Run AFTER seed:roles (and preferably seed:permissions). Re-run whenever
    seed:roles was just applied or role codes changed — users.role_id is
    re-derived from MSSQL flags against the current roles table.
    Required so client created_by / updated_by FKs resolve.
    Role mapping (priority top-down):
      IsAdmin            -> admin
      IsAdminAccount     -> account
      IsSubAdmin         -> admin (no built-in sub_admin)
      IsServiceProvider  -> kam
      IsClientWithLimit  -> client_limited
      IsClient           -> client
      otherwise          -> bidder
    Does not set is_owner from SEED_OWNER_EMAILS / SEED_OWNER_LOGIN (left as
    MSSQL/column default for now).
    Missing/0 created_by (and last_updated_by when last_updated_at is set)
    default to user id 1.
    email_id is seeded as-is from MSSQL (duplicates allowed; not unique).
    All users get password Welcome@123 (hashed via AUTH_PASSWORD_HASH);
    previous_password / forgot OTP cleared; password_changed = false.
    Does NOT set users.bidder_id — see B9.

        pnpm seed:users


B2. seed:clients — REQUIRED (prod)
    Source: MSSQL tbl_Config_ClientMst.
    RevenueRate → service_fee_value; service_fee_type = service_percentage
    when rate is in 0–5 (exclusive of 0). Null or 0 RevenueRate →
    service_fee_type = fixed_amount, service_fee_value = 0.
    Rows with invalid RevenueRate (negative or > 5) are skipped.
    Run AFTER seed:locations and seed:users.

        pnpm seed:clients


B3. seed:plant-locations — REQUIRED (prod)
    Source: MSSQL tbl_Config_PlantLocation.
    Seeds OrderNumber / OrderNumberDate → order_number / order_date.
    Does NOT seed ServiceFeePer (fee is client-level only).
    Run AFTER seed:locations, seed:users, seed:clients.
    Auction plant locations live on auction_lots.plant_location_id (not auctions).

        pnpm seed:plant-locations


B4. seed:material-locations — REQUIRED (prod)
    Source: MSSQL tbl_Config_MaterialLocation.
    Run AFTER seed:locations, seed:users, seed:clients.

        pnpm seed:material-locations


B4a. seed:uom — REQUIRED before auction lots
    Source: MSSQL tbl_Config_Item_UOM bare codes (PKg, PMT, …).
    Seeds only currency-prefixed codes used on lots: Rs{code} + AED{code}
    (e.g. RsPKg, AEDPKg). No bare PKg/PLt rows. Sequential ids 1..N.
    Clears existing uom_id FKs then replaces `uoms` — re-run seed:auction-lots after.

        pnpm seed:uom


B4b. seed:items — REQUIRED (prod)
    Source: MSSQL tbl_Config_ItemMst.
    Run AFTER seed:users, seed:clients, and seed:uom. material_id and uom_id left NULL when unknown.

        pnpm seed:items


B4b2. seed:service-invoices — REQUIRED (prod) for service invoice admin
    Source: MSSQL tbl_Data_ServiceInvoice.
    Run AFTER seed:users, seed:clients, and seed:plant-locations.
    Maps SRT 34/35/36 → service_percentage / fixed_amount / pmt.
    Skips Mixed (SRT 37) and prints skipped ids as a WARN.
    DB rows only — file uploads live in Phase R2 seed:service-invoice-documents.

        pnpm seed:service-invoices


B4b3. seed:service-invoice-payment-logs — REQUIRED (prod) for SI payment tracking
    Source: MSSQL tbl_Data_ServiceInvoicePaymentDetails.
    Run AFTER seed:service-invoices (and seed:users for created_by FKs).
    Upserts into service_invoice_payment_logs, then backfills
    service_invoices paid_amount / unpaid_amount / latest_payment_date / payment_status.

        pnpm seed:service-invoice-payment-logs


B4c. seed:benchmarks — REQUIRED (prod) for benchmark admin UI
    Source: MSSQL tbl_Config_MeterialLocationMap + tbl_Data_BenchMarkMeterials.
    Run AFTER seed:users. Populates benchmark_material_locations and benchmark_prices.
    Requires MSSQL_SERVER / MSSQL_* env (same as other Phase B seeds).

        pnpm seed:benchmarks

    Combos whose location contains "$" (e.g. LME$) are seeded as USD. Their prices
    are converted to INR with USD/INR rates from Frankfurter (ECB, no API key),
    cached in fx_rates; INR prices get exchange_rate 1 and price_inr = price.

B4d. db:backfill-benchmark-fx — ONE-TIME for databases seeded before currency support
    Marks "$" locations as USD, loads USD/INR rates into fx_rates (one API call per
    year), and fills currency / exchange_rate / price_inr / rate_date on every
    benchmark_prices row. --delete-junk drops legacy rows dated before 1999-01-04
    (the 1899-12-31 placeholders), which cannot be rated. Idempotent.

        pnpm db:backfill-benchmark-fx --delete-junk


B5. seed:validate-clients — VALIDATION STEP (not a data seed)
    FK integrity gate after client-related seeds. Exits non-zero on failure.
    Checks clients, plant_locations, material_locations FKs and prints counts.

=== Phase C — MSSQL → Postgres dependent ===


C1. seed:auctions — REQUIRED for auctions admin UI (optional in minimal dev)
    Source: MSSQL tbl_Data_Auction.
    Run AFTER seed:clients, seed:users, seed:plant-locations.
    Uses consolidated status model (draft/archived/published/closed).
    Flag map from tbl_Data_Auction:
      IsDeleted/IsArchived on unpublished → archived
      IsDeleted/IsArchived after publish/close → closed
      IsClosed / IsCanceled / IsApproved → closed
      IsPublished → published
      else → draft
    Live/upcoming/future are datetime filters over published auctions (not statuses).
    published → closed transitions are explicit only (seed IsClosed, future cron).

        pnpm seed:auctions

C1a0. seed:auction-bids — English bid ledger (auction_bids)
    Source (MSSQL → Postgres auction_bids): tbl_Data_AuctionTransaction only
      LotID→lot_id, AuctionId→auction_id, BidderCompId→bidder_id,
      BidderUserId→user_id, BidAmount→amount,
      IsProxyBid→is_proxy, ProxyBidAmount→proxy_amount,
      CreateDatetime→created_at (no IP column → ip null)

    Yankee (tbl_Data_YankeeTransaction) and sealed (tbl_Data_OnlineSealedBid)
    are NOT seeded here — different auction products; auction_bids is the
    English/forward live ledger. Sealed-bids go to auction_sealed_bids via
    seed:auction-sealed-bids. Denormalized lot counts come from the live and
    Yankee ledgers via seed:backfill-lot-bid-stats.

    auction_bids.id is identity — legacy IDs are not preserved.
    Soft-dedupe on (lot_id, bidder_id, amount, created_at).
    Skips orphans (lot/bidder/user missing in Postgres).
    Run AFTER seed:auction-lots, seed:bidders, seed:users.
    Optional: SEED_RESET=1 truncates auction_bids before reload.
    Prefer running BEFORE seed:backfill-lot-bid-stats.
    Default page size is 100k (same as other large seeds; override with
    SEED_BATCH_SIZE). Bulk UNNEST inserts; SEED_RESET skips soft-dedupe.

        pnpm seed:auction-bids
        SEED_RESET=1 pnpm seed:auction-bids
        SEED_RESET=1 SEED_BATCH_SIZE=10000 pnpm seed:auction-bids

C1d. seed:auction-additional-fields — OPTIONAL; client SAP-sync fields (Adani/HMSL)
    Source: MSSQL tbl_Data_AuctionAdditionalFields (legacy "Update Additional Field
    (Adani)" uploads; active rows only). tbl_Data_Auction_Additional_Fields is

C2. seed:emd — EMD ledger, refunds, forfeitures, settlement state (one transaction)
    Source: MSSQL tbl_Data_BidderPassBook, tbl_Data_PayEMD, tbl_Data_EMDForFeited,
    tbl_EMD_Book (deposit payment mode only).
    TRUNCATEs emd_transactions / emd_refunds / emd_forfeitures / emd_transfers /
    emd_range_holds / emd_winning_lot_releases / emd_settlement_jobs and reloads them:
      - PayEMD -> emd_refunds (PayId kept; status from AdminStatus/AccountStatus/
        TransactionId: UTR = paid, 'Cancel' = cancelled, rest open).
      - Passbook -> emd_transactions (TrnId kept). DR with auction = blocked,
        CR with auction = release_by_admin, CR without auction = deposit /
        opening_balance / refund_cancelled. Zero rows skipped.
      - Rows without an auction are matched (emd-legacy-match.ts):
          refund debit -> refund_requested (open) / refund_processed (paid),
            refund_id set (PayEMDId, UTR in remark, or bidder+amount near the request);
          cancel credit -> refund_cancelled with refund_id;
          EMDTransfer To/From pairs -> emd_transfers (approved) + transfer_out /
            transfer_in with transfer_id;
          other debits -> refund_processed (payout remark, no refund) or
            correction_debit.
      - Deposits: payment_type_id from tbl_EMD_Book (bidder + amount + UTR),
        else ICICI 696 when a UTR exists. Passbook LotEmdId -> emd_range_id.
      - Remaining blocks on closed auctions: winners get one range hold per won
        EMD range, taken forfeits a forfeited hold; everyone else stays
        blocked under a PAUSED legacy_cutover settlement job per auction.
        Resume those from the admin settlement screen after Accounts sign-off.
        Forfeitures whose block was already reversed in legacy are skipped and
        listed in the report.
      - ICICI 696 account number, VAN backfill, balance caches.
    Run AFTER seed:auctions, seed:auction-lots, seed:bidders, seed:bidder-bank-accounts,
    seed:users. Re-runnable (full reload).

        pnpm seed:emd

    seed.sh then runs seed:analyze (ANALYZE) so the verify queries below plan
    against fresh stats; without it emd:verify-holds can hit the statement timeout.

        pnpm seed:analyze


C3. emd:verify-seed — reconcile seeded EMD against MSSQL
    Per-bidder available balance must equal the legacy passbook net; blocked +
    winning per (auction, bidder) must equal the legacy passbook net on that auction;
    open refund totals must match. Exits 1 on any mismatch.
    Also prints (information only) refund/transfer link coverage, deposits
    without a payment mode, and legacy forfeitures that were not seeded.

        pnpm emd:verify-seed

C4. emd:verify-holds — read-only check of emd_range_holds (runs in seed.sh)
    Flags range-less holds that can be split, money held with every lot already
    released, lot releases hidden after a reopen, and holds that do not match the
    ledger. Each finding names the repair script. seed:emd already builds one
    hold per won EMD range, so a fresh load needs no repair script.
    Which script to run when, and when to delete them:
    docs/ops/emd-one-off-scripts.md

        pnpm emd:verify-holds


=== Phase R2 — file/document uploads to R2 ===
(Requires MSSQL_SERVER / MSSQL_* AND R2 credentials)

These seeds fetch legacy blobs/files and upload them to R2. They are split out
from the DB phases (A–C) so DB-only runs need no R2 credentials and stay fast.
Run them AFTER the DB phases (bidders/auctions + document-type rows must exist).

  ./src/db/seed/seed.sh --files-only   # just this phase
  ./src/db/seed/seed.sh                # DB phases + this phase (default)


R1. seed:bidder-documents — REQUIRED (prod) when legacy TempBidderInfo files available
    Unified MSSQL tbl_Data_BidderDocuments → TempBidderInfo fetch → R2 → bidder_document_logs.
    Truncates bidder_document_logs; clears orphan files rows for bidders/*.
    Writes file_name + s3_key on bidder_document_logs (no files table rows).
    Append-only: every MSSQL RecId becomes one log row. Fetches legacy TempBidderInfo
    file by MSSQL FileName; stores as `{prefix}{bidderId}_{epochMs}{ext}` using
    MSSQL CreatedDate (UTC epoch milliseconds). R2 key bidders/{storageFileName}.
    Backfills bank account cancelled cheque names from latest type-4 log entry
    (same UPDATE as seed:bidder-bank-accounts, so it heals rows seeded earlier).

        pnpm seed:bidder-documents [--report=/tmp/doc-files.csv] [--limit=50]
            [--prescan-concurrency=20] [--no-prescan] [--no-skip-missing]
    Pre-scan (default): local dir listing or parallel HTTP HEAD. Skips rows
    whose legacy file is missing, then uploads the rest to R2.

    Run AFTER Phase B (seed:bidders, seed:bidder-document-types, seed:bidder-bank-accounts).


R2. seed:auction-documents — REQUIRED for creation Documents tab (catalogue + TnC)
    Source: MSSQL tbl_Data_AuctionCatalog + tbl_Data_AuctionTnC (varbinary → R2).
    Seeds auction_documents used by the admin creation Documents tab (catalogue + TnC).
    Two-phase: validate blob (≤5MB, pdf/docx magic) + keep one per auction per document_type_id,
    then putObject + objectExists before DB insert.
    Writes file_name + s3_key on auction_documents (canonical basename; no files table).
    Naming: {prefix}{clientId}_{auctionId}_{epoch}{ext} under auctions/catalogues/|tnc/.
    UNIQUE(auction_id, document_type_id). Requires R2 credentials.
    Run AFTER seed:auctions and seed:auction-document-types (Phase A/C).
    Optional: --report=path.csv --limit=N

        pnpm seed:auction-documents


R3. seed:service-invoice-documents — REQUIRED (prod) when legacy SI files available
    Source: MSSQL tbl_Data_ServiceInvoice file names + local legacy dirs → R2 →
    service_invoice_documents (1:1 replace/upsert per invoice + type; stable R2 keys
    without epochMs: annexure_xlsx_{id}_{clientId}.xlsx / annexure_pdf_… / invoice_pdf_…).
    Run AFTER seed:service-invoices and seed:service-invoice-document-types (and db:push
    for service_invoice_documents). Prefer a clean reseed after the logs→documents cutover.
    Idempotent: skips (invoice, type) that already have an active row with s3_key.
      1) Annexure xlsx from LEGACY_SERVICE_INVOICE_ANNEXURE_DIR (UploadedFiles/InvoiceAnnexure)
         → document_type_id=1 (Annexure XLSX)
      2) PDFs from LEGACY_SERVICE_INVOICE_PDF_DIR (PdfInvoiceFiles/ServiceInvoiceInfo)
         via FileName split → type 2 Annexure PDF / type 3 Invoice PDF
      3) Auto annexure fallback: regenerate .xlsx from lifting logs for Auto rows
         still missing type-1 document

        LEGACY_SERVICE_INVOICE_ANNEXURE_DIR=/path/to/UploadedFiles/InvoiceAnnexure \
        LEGACY_SERVICE_INVOICE_PDF_DIR=/path/to/PdfInvoiceFiles/ServiceInvoiceInfo \
        pnpm seed:service-invoice-documents


R4. seed:subscription-documents — REQUIRED (prod) when legacy subscription invoice PDFs available
    Source: MSSQL tbl_Data_PaymentTransaction.FileName + LEGACY_SUBSCRIPTION_INVOICE_PDF_DIR
    (PdfInvoiceFiles/PaymentInfoReport) → R2 → subscription_documents
    (document_type_id=1 Invoice PDF; stable key subscriptions/subscription-{id}-{bidderId}.pdf).
    Run AFTER seed:subscriptions and seed:subscription-document-types.
    Idempotent: skips (subscription, type) that already have an active row with s3_key.
    Also patches invoice_status=generated when a PDF is uploaded and status was still requested.

        LEGACY_SUBSCRIPTION_INVOICE_PDF_DIR=/path/to/PdfInvoiceFiles/PaymentInfoReport \
        pnpm seed:subscription-documents


Document storage note (after denorm / db:push):
  Domain tables own file_name + s3_key. Prefer truncate + reseed for auction documents /
  bidder docs / service invoice documents / subscription documents (stable keys overwrite on reseed).
  Optional orphan cleanup (keeps misc users/* uploads):
    DELETE FROM files WHERE s3_key LIKE 'auctions/%' OR s3_key LIKE 'bidders/%' OR s3_key LIKE 'clients/%';
